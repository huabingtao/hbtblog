# LLM 前端流式传输与 UI 渲染策略笔记

## UI 渲染与呈现架构

### 1. 增量 Markdown 流式渲染（Standard Typewriter）
- **做法**：前端把收到的增量字符实时追加到字符串中，传给 `react-markdown` 或 `marked` 等解析器编译为 HTML 进行渲染。
- **难点与优化**：流式传输过程中，代码块（如 ```）或 LaTeX 公式（如 $$）的闭合标签可能尚未传输完毕，直接解析容易导致样式崩溃或内容结构错乱。通常需要使用**抽象语法树（AST）容错解析器**，或者在解析前自动补全未闭合标签。

### 2. 帧合并平滑打字机（rAF + Buffer Queue）
- **做法**：网络层接收到的字符先写入内存缓冲队列（Buffer Queue）中，UI 侧通过 `requestAnimationFrame`（按每秒 60 帧，即每帧约 16.6ms）匀速消耗队列里的字符并驱动界面渲染。
- **优势**：**彻底隔离网络抖动与冲刷**。即使大模型因网络延迟产生卡顿后突然一次性吐出大量字符，前端界面依然能维持极为平滑的打字效果，避免高频重绘带来的页面闪烁与卡顿掉帧。
